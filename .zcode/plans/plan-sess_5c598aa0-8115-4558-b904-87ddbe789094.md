# Mandatory `phone` field for every user

Format (user-locked): **loose digits** — `^\+?\d{6,15}$` (optional leading `+`, 6–15 digits). **Not unique.** **Officer-visible** in member/RSVP lists, CSVs, and search.

## Backend

**1. `backend/prisma/schema.prisma`** — `User` model: add `phone String` after `name`. No default → NOT NULL at DB level, provably mandatory.

**2. New hand-written migration** (repo convention — `migrate dev` is non-interactive-unsafe): `backend/prisma/migrations/20260817000000_add_user_phone/migration.sql`:
```sql
-- AddColumn: mandatory phone; backfill placeholder for pre-existing rows before NOT NULL
ALTER TABLE "User" ADD COLUMN "phone" TEXT;
UPDATE "User" SET "phone" = '0000000000';
ALTER TABLE "User" ALTER COLUMN "phone" SET NOT NULL;
```

**3. `src/modules/auth/auth.schemas.js`** — shared field const (DRY between register/updateProfile):
```js
const phoneField = z.string().trim().regex(/^\+?\d{6,15}$/, 'Phone must be 6-15 digits, optionally starting with +');
```
`register` gains `phone: phoneField` (required). `updateProfile` gains `phone: phoneField.optional()`. Must be declared — `validate()` middleware replaces `req.body` with Zod-parsed data and strips unknown keys, so an undeclared field is silently dropped.

**4. `src/modules/auth/auth.controller.js`** — register destructure gains `phone`; pass through.

**5. `src/modules/auth/auth.service.js`** —
- `register(email, password, name, phone)`: `data` gains `phone`; select gains `phone: true`.
- `login` hand-rolled `userWithoutPassword` gains `phone` (required — AuthContext register→login seeds `user` state that Profile reads).
- `getMe` and `updateProfile` selects gain `phone: true`; `updateProfile(userId, { name, email, phone })` with `if (phone !== undefined) data.phone = phone;`. Empty-string phone fails the regex → phone can never be cleared (correct for a mandatory field).

**6. Officer visibility (locked: yes):**
- `src/modules/memberships/memberships.service.js`: `USER_SELECT` gains `phone: true` (flows to member list, join requests, status updates, promote/demote, transfer). `exportMembersCsv`: header → `Name,Email,Phone,Role,Status,Joined Date`, row gains phone column.
- `src/modules/rsvp/rsvp.service.js`: `listByEvent` and `exportRsvpsCsv` user selects gain `phone: true`; CSV header → `Name,Email,Phone,Status,Responded At`.
- `src/utils/search.js`: `userSearchWhere` OR gains `{ phone: { contains: q, mode: 'insensitive' } }`.

**7. Swagger (`auth.routes.js`)** — register block: `required` gains `phone`, property added; also drop the stale `confirmPassword` entries (pre-existing doc bug in the same block — schema never had it). Profile block: property added.

**8. `prisma/seed.js`** — each of the 18 `userData` entries gains a distinct realistic phone (`+8801710000001` … `+8801710000018`); `create` payload gains `phone: u.phone`.

**9. Tests** —
- `tests/fixtures/index.js` `makeUser`: data gains `phone: overrides.phone || '01700000000'`; select gains `phone: true`. (Constant OK — not unique.)
- `tests/api/auth.test.js`: `valid` gains `phone: '01712345678'`; 201 test asserts `phone` in body; new cases: invalid phone on register → 400, profile phone update → 200 + body, invalid phone on profile → 400.
- Extend members-CSV and rsvps-CSV tests to assert the `Phone` header appears in the body.

**12. `src/pages/Profile.jsx`** — `phone` state seeded from `user?.phone`; input block after Email (same attrs as Register); PATCH body gains `phone`.

**13. Officer UI display** (read each file before editing, per AGENTS rule): `src/pages/admin/ClubMembers.jsx` and `src/pages/EventRsvps.jsx` — render phone as `text-xs text-muted-foreground` under the email line; update both search placeholders to "name, email, or phone".

## Deliberate exclusions (not gaps)
- Announcements author / audit actor / RSVP self-row selects: name-only by design — no contact use case.
- `clubs.service.getById` member include: ClubDetail renders name+badge only; officers get phone via the members endpoint.
- `PendingRequests.jsx`: payload will carry phone (USER_SELECT) but no UI line — approving a join needs no contact info.

## Apply & verify
1. From `backend/`: `npx prisma migrate reset --force` (replays all migrations on empty DB, exercises the new SQL) → `npx prisma generate` → seed (`reset` auto-seeds if configured; else run seed script). Dev DB is seed-driven, so reset is the clean path — avoids placeholder rows the re-run-safe seed won't backfill (`update: {}` upsert).
2. `npx jest --runInBand --forceExit tests/api/auth.test.js tests/api/memberships.test.js tests/api/rsvp.test.js` (Docker required — testcontainers Postgres; serialized per repo rule).
3. `frontend/`: `npm run build` to catch JSX regressions.
