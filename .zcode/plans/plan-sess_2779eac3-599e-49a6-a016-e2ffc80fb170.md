# Fix ClubSearchPicker dropdown trapped inside dialogs

## Root cause
`ClubSearchPicker.jsx` renders its results list as `position: absolute` inside a `relative` wrapper — not portaled. `DialogContent` (`components/ui/dialog.jsx:29`) bakes in `max-h-[90vh] overflow-y-auto`, so the abs-positioned list is clipped by and adds scrollable overflow to the dialog. With the picker at the bottom of both host dialogs, results are only reachable by scrolling the modal.

## Scope (verified by full-frontend sweep)
The inline-dropdown pattern exists in exactly ONE component (`ClubSearchPicker`), used in exactly 2 places, both inside `DialogContent`:
- `components/event/ManageCoHostsDialog.jsx:101` (reported instance)
- `pages/ClubDetail.jsx:148` (Create Event dialog — same bug)

All other overlays are Radix Selects (already portaled + `max-h-96`, safe). One component fix covers everything. No prop API changes — both call sites untouched.

## Changes

### 1. Install dependency
`npm install @radix-ui/react-popover` in `frontend/` (React-19-compatible ^1.1.x, consistent with existing 5 Radix packages).

### 2. New primitive `frontend/src/components/ui/popover.jsx` (~25 lines)
shadcn-style JSX (repo uses `"tsx": false`), conventions copied from `dropdown-menu.jsx`:
- Exports: `Popover`, `PopoverTrigger`, `PopoverAnchor`, `PopoverContent`
- `PopoverContent`: `PopoverPrimitive.Portal` → Content with `align="start"`, `sideOffset={4}`, classes `t-dropdown z-50 rounded-md border bg-popover text-popover-foreground shadow-md outline-none` (reuses existing `t-dropdown` keyframes incl. reduced-motion gating; `bg-popover` token already used by dropdown-menu)

### 3. Rework `frontend/src/components/event/ClubSearchPicker.jsx`
Keep: debounce fetch effect, `excludeIds` filtering, loading/empty/results row markup, `pick()` reset.
Replace rendering with:
```jsx
<Popover open={open && query.trim().length > 0} onOpenChange={setOpen}>
  <PopoverAnchor asChild>
    <div ref={anchorRef} className="relative">
      <Search ... />
      <Input ... onFocus={() => setOpen(true)} />
    </div>
  </PopoverAnchor>
  <PopoverContent
    className="w-[var(--radix-popover-anchor-width)] p-1 max-h-[min(15rem,var(--radix-popover-content-available-height))] overflow-y-auto"
    onOpenAutoFocus={(e) => e.preventDefault()}
    onPointerDownOutside={(e) => { if (anchorRef.current?.contains(e.target)) e.preventDefault(); }}
  >
    {/* loading / no-results / results.map — unchanged */}
  </PopoverContent>
</Popover>
```
- Delete the manual `document.mousedown` outside-click effect (Radix DismissableLayer replaces it).
- `onOpenAutoFocus` prevented → focus/caret stays in the input while typing.
- `onPointerDownOutside` guard → clicking the input itself (cursor reposition) doesn't dismiss; all other outside clicks do.
- Height cap: `max-h-[min(15rem,var(--radix-popover-content-available-height))]` + internal `overflow-y-auto` → hard cap AND viewport-aware (Radix collision-flip opens it above the input when the dialog sits near the viewport bottom).
- Escape now closes only the list (topmost Radix layer), not the whole dialog — small UX improvement over current behavior.

### 4. Verify CSS variable names during implementation
Confirm `--radix-popover-anchor-width` and `--radix-popover-content-available-height` are set on the rendered content (browser devtools). Fallback if absent: measure anchor via `getBoundingClientRect()` and pass inline `style={{ width }}`.
